## &nbsp;⚡&nbsp; About

> I build the software companies run their day on. Not demos — systems that hold other
> people's invoices, clients and deadlines, where a bug costs real money and real trust.

**Head Developer at [DGTalit](https://www.dgtalit.com/)**, leading a multi-tenant ERP/CRM SaaS in production
for client companies: quoting and invoicing with Spanish **VeriFactu** tax compliance, CRM pipelines, project
and ticket management, queued background jobs, and a fully trilingual interface (ES / EN / CA).

<table>
<tr>
<td width="50%" valign="top">

**🔐 Tenant isolation**

Every data path answers one question first: *can a user of tenant A reach tenant B through here?*
Session-derived scoping, server-side permission checks, immutable audit trails.

</td>
<td width="50%" valign="top">

**🧱 Change that doesn't break**

Additive-only schemas, backwards-compatible APIs, migrations that cannot lose a row, and a rollback
plan written before the deploy rather than after it.

</td>
</tr>
<tr>
<td width="50%" valign="top">

**⚖️ Regulated & financial data**

Spanish e-invoicing, money as integers in cents, UTC-first timestamps, GDPR / LOPDGDD subject rights,
soft deletes over destructive ones.

</td>
<td width="50%" valign="top">

**🚢 Shipping without a net**

Direct-to-production deploys on self-managed VPS infrastructure — excellent training in caring about
the thing *before* you push it.

</td>
</tr>
</table>

<details>
<summary><b>&nbsp;📌&nbsp; How I work &nbsp;<sub>(click to expand)</sub></b></summary>

<br>

- **Read before writing.** I read the whole file and every call site before changing a signature. Most
  production incidents are someone's confident partial read.
- **Smallest change that solves it.** No drive-by refactors inside a bugfix. Reviewers should be able to
  tell exactly what moved.
- **The server decides.** Hiding a button is not authorisation. Permission checks live where they cannot
  be bypassed.
- **Types as the first test.** Strict TypeScript end to end, no `any`, no silent `@ts-ignore`.
- **Boring where it counts.** Transactions around multi-table writes, pagination on anything that grows,
  indexes on anything filtered, queues for anything slow.

</details>
